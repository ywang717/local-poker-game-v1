# Local Poker Game V2.0 设计规格

## 目标与范围

V2.0 在现有离线中文单机扑克游戏上增加三项相互协作但可独立测试的能力：

1. LV2–LV5 的范围驱动 AI，明确区分 Open、3-Bet、4-Bet、All-in 和翻牌后策略。
2. 六人 Mini 锦标赛，支持动态淘汰、盲注升级、Heads-Up 和一次性冠军奖金。
3. 普通现金桌的中途买入，采用预留资金、下一手生效和幂等退款。

现有扑克规则引擎、离线运行、IndexedDB、PWA、中文白色 UI、AI 信息边界和 14,000 手规则压力测试继续保留。V2.0 不引入联网、账号、真人联机或外部 GTO Solver。

## 设计决策

### 比赛类型与会话模型

新增 `MatchType = 'CASH' | 'MINI_TOURNAMENT'`。`GameState` 保存 `matchType`、`tableLevel` 和稳定的 `sessionId`；旧存档通过迁移默认到 `CASH` 和从大盲推导的桌级。锦标赛的 AI 等级永远读取报名时保存的 `tableLevel`，不从不断增长的当前大盲推导。

新增 `TournamentState` 作为会话元数据，包含 `tournamentId`、模式、报名等级、当前盲注阶段、阶段手数、参赛者、淘汰记录、最终排名、冠军、报名费、奖金和 `rewardPaid`。普通现金桌不创建该对象。

为了复用下注和结算引擎，锦标赛仍使用 `GameState`；淘汰玩家会在一手结算后从下一手玩家列表移除。庄位模块新增基于实际存活座位的行动顺序和盲注计算，解决六人桌缩减到 Heads-Up 后的盲注与行动顺序问题。

### 资金与幂等交易

`CareerState` 新增版本化资金流水、待生效现金买入和锦标赛统计。资金交易使用唯一 `transactionId`、会话 ID、金额、类型、时间和状态，交易服务在重复调用时返回已有结果而不重复扣款或退款。

现金桌买入分为：初始买入、待生效补码、下一手实际应用、未使用部分退款、离桌兑现。申请时从生涯账户预留资金；当前手牌的 `GameState` 不改变；结算后按 `min(申请金额, 100BB - 实际桌上筹码)` 应用，余款自动退回。离桌会先取消待生效交易，再兑现实际桌上筹码。

锦标赛报名费只扣一次，比赛筹码不写入现金桌利润；冠军奖金只由 `rewardPaid` 守卫发放一次。真人筹码归零时现金桌显示重新买入/离桌选择，锦标赛则直接淘汰。

### AI V2 决策边界

保留 `chooseAction` 的可调用入口，内部改为分层决策：

1. 从公开上下文读取模式、位置、街道、有效筹码、行动历史和对手模型。
2. `classifyPreflopSituation` 区分 unopened、limped、facing open、facing 3-Bet、facing 4-Bet+ 和 facing All-in，并忽略盲注本身和短码不完整加注作为新的完整加注。
3. 以标准德州 169 类、短牌 81 类的组合权重范围表选择 Open、Call、3-Bet value/bluff、4-Bet value/bluff 和继续面对 All-in 的策略。
4. 位置策略使用固定座位位置；BTN、CO、HJ、MP、UTG 等映射由人数和庄位决定，弃牌不会改变位置。
5. 独立的 `raiseSizing`、`jamDecision` 和 `postflopStrategy` 负责尺度与全下门控。100BB 主要使用常规加注；20–30BB 才逐步允许 4-Bet jam；10–15BB 才提高 Push/Fold 比重。
6. LV2–LV5 通过范围质量、对手模型权重、混合频率和底池控制能力提升，而非无条件增加激进度。性格只做小幅偏移，不能突破级别范围。

每个 AI 决策都经过引擎 `getLegalActions` 校验。随机源可注入，发牌随机流和决策随机流在模拟器中分离；AI 仍不能读取真人底牌、未公开底牌、牌堆、未来公共牌或结果。

### Mini 锦标赛

新增 `src/tournament/` 纯逻辑模块：报名、六人初始筹码、盲注表、每八手升级、淘汰、排名、Heads-Up、冠军奖励和观战状态。比赛每手结束后才判断淘汰；多名同手归零玩家按该手开始筹码和稳定座位顺序生成确定排名。存活人数只能减少，比赛总筹码在无奖金发放前守恒。

锦标赛 AI 使用现金桌 AI 的范围和 postflop 核心，但额外传入比赛阶段、存活人数、筹码排名、有效筹码和淘汰风险。报名等级固定 AI 难度。真人提前淘汰后保留观战/快速模拟入口，不出现现金桌买入按钮。

### 存档迁移与恢复

`saveVersion` 提升为 2。迁移为旧职业存档填充空流水、空锦标赛统计和无待买入；旧牌局快照填充 `matchType: 'CASH'`、默认桌级和空会话元数据。保存时保留当前/备份记录，交易状态通过幂等 ID 在恢复时继续、应用或退款，不重复执行。

## UI 结构

- 生涯主页增加“Mini 锦标赛”入口和独立锦标赛统计。
- 现金牌桌工具栏增加“买入”；当前手牌期间显示待生效金额和下一手提示。
- 结算且真人筹码为零时显示“重新买入”和“离开牌桌”。
- 锦标赛牌桌显示存活人数、阶段盲注、下次升级、筹码排名、淘汰记录和冠军奖金；不显示买入按钮。
- 继续使用当前白色极简响应式布局，移动端按钮保持触控尺寸，核心牌桌不改为翻页流程。

## 测试与发布门禁

先保存同一随机配置下的 LV2–LV5 标准/短牌 10,000 手基线，再运行修改后同矩阵并输出实际分子/分母：VPIP、PFR、3-Bet、4-Bet、Fold to 3-Bet、C-Bet、Check-Raise、主动/跟注/街道 All-in、平均底池、加注尺度、摊牌率和行动数。

新增：

- AI 定点场景与每等级/模式至少 10,000 次决策抽样。
- 现金买入纯函数、当前手不变、下一手应用、归零重买、取消退款、重复点击和恢复测试。
- 标准/短牌各 500 场、LV2–LV5 均匀分配的完整锦标赛，加上 LV1 基础测试。
- 保留原有 14,000 手规则回归，并增加 Duplicate Payout、锦标赛守恒和观战恢复断言。
- AI 平均/P95/最大决策耗时和移动 UI 回归。

GitHub Pages 发布顺序固定为 `npm ci`、`npm run typecheck`、`npm test`、`npm run test:ai`、`npm run test:ai:experience`、`npm run test:cash-buyin`、`npm run test:tournament`、`npm run test:simulation`、`npm run build`；任一失败都不部署。

## 开源参考边界

PyPokerEngine 的 MIT 许可和 AI callback/emulator 组织方式可作为接口设计参考；`thotbreakerr/Texas-Holdem-AI` 的分层 bot、锦标赛上下文和 sanity gate 可作为测试组织参考；`rosbo/texas-holdem-poker-ai` 的阶段化策略和对手模型可作为概念参考。实现使用本项目现有 TypeScript 规则和数据结构，不复制外部代码、范围表或训练数据。
