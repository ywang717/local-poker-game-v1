# 结算继续与上一手回顾设计

## 目标

每手牌结算后暂停在结果画面，由玩家选择继续下一手或离开牌桌；牌桌内提供上一手的可展开回顾，展示已公开的牌面、底池结算和行动时间线。

## 范围

- 移除结算后自动开始下一手的定时器。
- `SETTLEMENT` 状态显示“继续下一手”和“离开牌桌”。
- 继续时轮换庄位、补充输光的 AI 筹码、创建并保存下一手。
- 离开时按现有资金、统计和破产保护流程结算并返回生涯页。
- 复用 `HandSummary` 作为回顾数据源；结算完成后写入生涯记录，下一手开始后使用最近一手记录作为上一手。
- 牌桌内默认展开上一手回顾；进入下一手后用“查看上一手”按钮展开或收起。
- 回顾展示玩家底牌、公共牌、最终牌型、底池、结果、行动时间线和各底池获胜者/派奖。
- 弃牌 AI 的底牌保持隐藏；只有摊牌时已公开的底牌可展示。
- 当前手牌快照继续保存 `SETTLEMENT` 状态，重启后可继续选择。

## 交互流程

```text
SHOWDOWN → SETTLEMENT
              ├─ 继续下一手 → HAND_START / PRE_FLOP
              └─ 离开牌桌 → 生涯页
```

结算时真人筹码为 0，继续按钮禁用，离开按钮仍可执行破产保护。进行中的离桌请求仍在本手完成结算后离开，不被新的继续按钮绕过。

## 数据与模块

- `App` 负责结算记录、继续下一手和离桌回调，不再通过 effect 定时推进。
- `GamePage` 负责结算控制区和上一手回顾展开状态。
- 新的 `HandReview` 组件负责回顾布局，历史页与牌桌页共享同一展示组件。
- `HandSummary` 增加每个底池的获胜者与派奖信息，或使用等价的可序列化字段；旧记录迁移时使用空数组默认值。
- 手牌编号必须跨离桌重进保持唯一，不能仅依赖牌桌内的 `handNumber`。
- IndexedDB 继续保存 career、handHistory 和 currentHand；不新增网络或服务端依赖。

## 非目标

- 不新增动画回放。
- 不改变下注规则、AI 信息边界、底池算法或资金规则。
- 不增加联网、账号、服务器或真钱功能。

## 验收标准

1. 结算后不会自动开始下一手。
2. 点击继续才开始下一手；点击离开返回生涯页。
3. 结算快照重启后仍显示两个选择。
4. 上一手回顾能在结算时默认看到，并可在下一手中展开/收起。
5. 回顾数据与手牌历史一致，行动时间线和底池获胜者不丢失。
6. 连续多手不会出现重复 Hand ID。
